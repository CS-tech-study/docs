# IPC (Inter Process Communication)

## 개요

### 정의

운영체제 내에서 서로 독립적인 프로세스들이 데이터를 주고받거나 자원을 공유할 수 있도록 하는 통신 메커니즘

### 사용 이유

일반적으로 각 프로세스는 고유의 주소 공간을 가지기 때문에 직접 메모리를 공유할 수 없습니다.

때문에 동기화, 자원 공유 등을 위해서는 IPC 기법을 이용해야합니다.

![image.png](/os/images/ipc.png)

## 기법 - 공유 메모리

### 공유 메모리

여러 프로세스가 동일한 메모리 영역을 공유하여 데이터를 직접 읽고 쓸 수 있도록 하는 기법입니다.

- 장점
    - 빠른 속도
    - 커널의 개입없이 메모리에 접근 가능합니다. → 적은 오버헤드
- 단점
    - 동시성 문제가 발생할 수 있습니다.
- 언제 사용?
    - 대량의 데이터를 빠르게 공유해야할 때 사용합니다.

### 메모리 맵 파일

파일의 내용을 메모리에 맵핑하여, 파일 I/O 대신 메모리 접근처럼 데이터를 처리할 수 있게 하는 기법입니다.

![image.png](/os/images/memorymap.png)

- 장점
    - 파일 IO 보다 빠른 메모리 IO로 접근 가능합니다.
- 단점
    - 메모리와 파일 간의 데이터 불일치 가능합니다.
- 언제 사용?
    - 파일로 대용량 데이터를 공유 할 때, FILE IO가 느릴 때  사용합니다.

## 기법 - 메시지 전달 (Message Passing)

### 파이프, 네임드 파이프

파이프는 한 프로세스의 출력 데이터를 다른 프로세스의 입력으로 전달하는 단방향 통신 메커니즘입니다.

네임드 파이프는 이름을 가지는 파이프로, 서로 다른 프로세스들이 PIPE의 이름만 알면 통신이 가능합니다.

- 장점
    - 네임드의 경우 서로 다른 프로세스 간 PIPE의 이름만 알면 통신이 가능합니다.
- 단점
    - 단방향 통신 → 쌍방 통신을 위해서는 Write용, Read용 PIPE 모두 필요합니다.
- 언제 사용?
    - 부모 자식 프로세스간 통신 할 때 사용합니다.

### Message Queue

메모리에서 동작하는 PIPE로 메시지 단위로 통신하는 특징이 있습니다.

각 메시지는 IFO(선입선출) 방식으로 저장되어 비동기적으로 전달됩니다.

![image.png](/os/images/messagequeue.png)

- 장점
    - 파이프와 달리 다수의 프로세스에게 메시지를 전달 가능합니다.
- 단점
    - 커널에서 제공하는 Message queue기 때문에 EnQueue에 제한이 존재합니다 
    = 커널 쓰레드에서만 가능 하다는 뜻?
- 언제 사용?
    - 채팅 서비스, 배치 처리, 분산 시스템 등에서 데이터를 비동기적으로 주고받을 때 사용합니다.

### Socket

네트워크 소켓통신을 시용하는 방식을 말합니다.

- 언제 사용?
    - 클라이언트-서버 모델 등 원격 통신을 할 때, 외부에 프로세스가 존재할 때 사용합니다.

### RPC (Remote Procedure Call)

클라이언트가 자신의 로컬 주소 공간에서 호출하는 것처럼, 원격 서버의 프로시저(함수나 메서드)를 실행할 수 있게 하는 분산 통신 기술입니다.

![image.png](/os/images/rpc.png)

- **장점**
    - IDL을 사용하여 서로 다른 플랫폼 간의 통신이 가능하게 합니다.
- 단점
    - 네트워크, 패킷 손실 등의 문제로 인해 실제로는  로컬 함수 호출보다 훨씬 느릴 수 있습니다.
    - 네트워크를 통한 통신이므로 인증, 암호화 등의 보안 메커니즘이 필수적입니다.
- 언제 사용?
    - MSA, 클라이언트-서버 모델, 원격 시스템 등에서 통신이 필요할 때 사용합니다.
