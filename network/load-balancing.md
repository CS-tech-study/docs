## Load Balancing

### 개념


> 로드 밸런싱은 애플리케이션을 지원하는 리소스 풀 전체에 네트워크 트래픽을 균등하게 배포하는 방법입니다.

### 장점


- 가용성
    
    > A와 B 애플리케이션이 동작하고 있을 때, A에 장애가 발생한다면?
    > 
    
    로드밸런싱을 이용해서 B로 요청을 보냅니다.
    
    → 사용자는 서버에 장애가 발생했는지 조차 모르고 그 사이에 A를 복구할 수 있습니다.
    
- 확장성
    
    > 앱이 너무 잘돼서 더욱 많은 컴퓨팅 리소스가 필요해진다면?
    > 
    
    다른 설정 없이 새로운 리소스만 생성해서 로드 밸런싱에 추가만 해놓으면 바로 사용 가능합니다.
    
    + 오토 스케일링
    
    AWS의 Elastic Load Balancing, GCP 등 클라우드에서 자동으로 라우팅을 최적화하는 오토 스케일링을 지원
    
- 보안
    
    > DDOS 등의 공격이 들어온다면?
    > 
    
    로드 밸런서에 모니터링 도구를 붙여 악성 접속을 애플리케이션에 부하 없이 차단 가능합니다.
    

### 알고리즘

- 정적
    - 라운드 로빈
        
        = 차례대로
        
    - 가중치 기반 라운드 로빈
        
        = 우선 순위를 미리 정해 놓고 가중치가 높은 서버쪽으로 더 많이
        
    - IP 해시
        
        = 클라이언트의 IP로 해시값을 만들어서 개별 서버로 
        
- 동적
    - 최소 연결
        
        = 클라이언트와의 연결이 가장 적은 서버로
        
        단, 모든 서버가 동일한 처리 능력이 있다고 가정
        
    - 가중치 기반 최소 연결
        
        = 서버 별로 처리 능력이 다를 경우 우선순위를 정한 후 용량별 연결이 가장 적은 서버로
        
    - 최소 응답 시간
        
        = 요청을 처리하고, 응답을 전송하는데 걸리는 총 시간이 가장 적은 서버로
        
    - 리소스
        
        = 현재 서버의 용량 및 메모리와 같은 리소스 사용량을 계산해서 가장 여유 있는 서버로
        

## Load Balancer

### 종류

- L4
    - OSI 4계층 (전송 계층) 기반
    - 포트 번호를 바탕으로 부하 분산
    - 한 대의 서버가 각각 다른 포트 번호를 부여해서 다수의 프로그램을 운영하는 경우 사용
- L7
    - OSI 7계층 (애플리케이션 계층) 기반
    - HTTP 헤더, 쿠키 등의 사용자 요청정보를 기준으로 부하 분산
