## GET

- 용도
    - 서버로부터 정보를 받기 위해 사용합니다.
- 리소스를 서버에 전달할 때
    - 쿼리 스트링을 사용합니다.
        
        ex) http://example.com/api/items?category=books&page=2
        
        → URL 길이에 제한이 있어 보낼 수 있는 데이터 길이에 제한이 있습니다.
        
        → URL에 그대로 데이터가 노출되기 때문에 보안적으로 취약합니다. 
        
- 캐싱
    - 브라우저 히스토리에 기록되고, 캐싱이 가능합니다.
        
        → 동일한 요청에 대해 빠른 응답을 제공할 수 있습니다.
        
        → 북마크에 추가도 가능합니다.
        
- 응답
    - 성공시 HTTP응답코드로 200(OK)를 반환합니다.
- 멱등성이 보장됩니다.

## POST

- 용도
    - 서버에 새로운 리소스를 생성 (or 변경) 하기 위해 사용합니다.
- 리소스를 서버에 전달할 때
    - HTTP 메시지의 Body에 담아 전송합니다.
        
        → Body에 담아보내기 때문에 데이터 길이에 제한이 거의 없습니다.
        
        → 상대적으로 보안에 유리하지만, 네트워크상에서는 암호화 통신(SSL)을 사용해야합니다.
        
- 캐싱
    - 브라우저 히스토리에 기록되지 않고, 캐싱이 불가능합니다.
        - 이는 서버에 변화를 요청하는 것이기 멱등성이 보장되지 않기)때문에 캐싱을 할 수 없습니다.
- 응답
    - 성공시 HTTP응답코드로 201(CREATED)를 반환합니다.
- 멱등성이 보장되지 않습니다.

### 멱등성 (Idempotent)

***같은 요청(연산)에 대해 항상 동일한 결과가 반환되는 것***을 말합니다.

- GET
    - 동일한 GET 요청을 여러 번 보내더라도 서버의 상태나 응답 결과는 변하지 않아야 합니다.
- POST
    - 동일한 POST 요청을 여러 번 보내면 서버에 중복된 데이터 생성이나 상태 변화가 발생할 수 있습니다.

## PUT & PATCH & DELETE

GET과 POST의 차이는 확실히 알겠습니다. 하지만 POST와 PUT, PATCH 등 다른 메소드는 어떤 차이가 있을까요?

### PUT

- 용도
    - 리소스를 완전히 새로운 데이터로 대체할 때 사용합니다.
- 멱등성이 보장됩니다.
    - 항상 요청시에 보낸 데이터로 덮어씌우기 때문에 같은 요청을 여러 번 전송해도 같은 응답을 보장합니다.

### PATCH

- 용도
    - 리소스를일부분만을 수정할 목적으로 사용합니다.
- 멱등성이 보장되지 않습니다.
    - 만약 PATCH 요청으로 내부 비즈니스 로직에서 아래의 updateNumber()를 호출한다고 한다면 멱등성을 보장하지 않습니다.
        
        ```java
        public class Foo {
        	private int number;
         
          public void updateNumber() {
        	  this.number++;
          }
        }
        ```
        

### DELETE

- 용도
    - 리소스를 삭제할 때 사용합니다.
- Body 사용 X
    - 일반적으로 Body에 정보를 담아서 전달하지 않습니다.
    - 식별자만 담아서 전달하는 방식으로 사용됩니다.
- 멱등성
    - 동일한 DELETE 요청을 여러 번 보내더라도, 첫 번째 요청 후 대상 리소스가 삭제되므로 이후 요청은 이미 삭제된 상태를 유지하게 됩니다.

### 정리

- POST는 주로 새로운 리소스를 생성하거나 서버의 상태를 변경하는 작업에 사용되며, 같은 요청을 반복하면 여러 번 실행되어 부작용이 발생할 수 있습니다.
- PUT은 특정 URL에 대해 리소스를 “완전히 덮어쓰기”하는 작업에 사용되며, 동일한 요청을 반복해도 결과가 동일하게 유지됩니다.
- PATCH는 리소스를 “일부만 수정”할 목적으로 사용되며, 멱등성은 보장되지 않을 수 있습니다.
- DELETE는 리소스 삭제를 위해 사용되며, 한 번 삭제된 후 동일한 요청을 보내더라도 결과에 변화가 없으므로 멱등성을 가집니다.
